What standing does. It bounds which release lanes an org is eligible for: a partner org gets bilateral lanes and the broad lane, never an ally's default reach. There is no member-only lane — alliance members already read everything, so such a lane would grant nothing. Standing is an eligibility check, not a grant: nobody reads anything because of it until a release-lane or data grant is actually issued.

What standing does NOT do. It does not set this person's fabric read or write scope. Writes are per-anchor (each identity writes only its own <uuid>/** root); reads are flat across the goatnet unless the partner read partition carves this anchor, which is a deliberate per-anchor operator edit (zenoh_partner_read_lanes), not a consequence of standing. Partner standing alone changes nothing on the wire.

Why it is derived, not stored. Membership changes (Finland 2023-04-04, Sweden 2024-03-07), so standing rides the registry as currently-is and is deliberately absent from the frozen cert and from the Ory claim. It is resolved here from nation against the coalition framework registry, the one home for that fact — which is also why an edit there changes standing fleet-wide with no re-mint.
