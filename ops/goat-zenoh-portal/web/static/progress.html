__LEX_ORG_TITLE__ onboarding progress

Stage is the furthest step with positive evidence behind it — read that column first; it is the one that says where an onboarding stopped. The level columns behind it are the raw evidence: L1 bundle minted · L2 netbird peer enrolled · L3 hello-world publish observed · L4 non-hello publish observed. Stickiness is monotonic — L4 implies L3 in the UI even if the __LEX_ORG__ skipped the example.

Two distinctions this table refuses to blur. L1 is something the portal did (it minted a bundle), not something the person did — the Bundle column says whether the tarball was actually fetched, which is a different question with a different remedy. And declared topics (registered in the portal) are shown separately from observed ones (seen on the wire): declared-but-never-published is an integration that never started, published-but-never-declared is a publisher whose schemas the decode surfaces cannot render.

A blank cell means no evidence recorded, which is not the same as did not happen — bundle downloads have only been recorded since 2026-08-12, so rows minted before then read blank regardless. Nothing here records subscribe-side activity at all, so this table cannot tell you whether any one __LEX_ORG__ is receiving data. Synthetic __LEX_ORGS__ are hidden by default.
