Router Config Generator

For Flavor B (Router-peer) onboarding only — the path where you run your own zenohd and federate with us, rather than connecting a single publisher process directly. If you're going for Flavor A (Publisher), skip this page; the bundle the operator hands you already contains a worked first-publisher.py.

Punch in your intended __LEX_ORG__ prefix below and we'll render a copy-paste zenohd.json5 with our router endpoint, mTLS pinning, and the cert-path placeholders you need to bind-mount into the container. Same data as Our Config but pre-baked into the actual config format.

Your zenohd.json5


      


      

        
Next steps after generating

        
    
          
  1. Ask the operator to mint your __LEX_ORG__ row (Guide §4.1). They hand you a bundle containing cert.pem, key.pem, root-cert.pem.
    2. 
          
  2. Drop the generated config above into zenohd.json5 on your side. The cert paths are pre-set to /cert/... — bind-mount your bundle files into a directory mounted at /cert/ in the container, or edit the paths to wherever you've put them.
    3. 
          
  3. Start the container:

    docker run --rm -d --name my-zenoh \
  -v "$(pwd)/zenohd.json5:/zenoh.json5:ro" \
  -v "$(pwd)/bundle:/cert:ro" \
  -p 7447:7447 \
  eclipse/zenoh:1.9.0 -c /zenoh.json5
    
          
    4. 
          
  4. Point your downstream publishers + subscribers at tcp/127.0.0.1:7447. They don't need certs — the trust boundary is your router's upstream mTLS to us.
    5. 
          
  5. Verify federation on Inspector + Panoscope ↗.
    6. 
        

      


      

        Why not just curl the endpoint directly? You can. Same response:

curl -s "?prefix=<your-prefix>" > zenohd.json5

        The page is just a friendlier wrapper with copy/download + prefix-collision feedback.
