What this page is for

Each row below is a trashgoat spec: a defined publish shape (slug + topic_pattern + payload_spec + cadence_spec) that the runner can execute under the trashgoat/<slug>/… namespace. The runner subscribes to ops/trashgoat/control/<id>/v1 and acts on lifecycle events the portal emits when you activate / pause / retire / cleanse. Anything trashgoat publishes is suspect by construction; consumers must not depend on it.

PR #2 substrate only. Specs persist + lifecycle works + control-topic events are emitted on every state change, but the runner (goat-trashgoat) lands in PR #3. Activating a spec today is a no-op on the wire — nothing publishes yet.
