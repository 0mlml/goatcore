C ABI

The single audited FFI seam

Every binding — Go, Python, TypeScript — links this one hand-authored, versioned C ABI. Written in Rust (not C), prefix gc_, opaque handles only. It is the single choke point that keeps the count of real implementations at one. The header is generated by cbindgen, committed, and reviewed as source.

Versioning — lockstep, no cross-version promise

gc_abi_version() returns a monotone uint32_t. The core and the wrappers ship in lockstep from one release tag, SONAME-pinned, so there is no cross-version ABI promise. Pull the library and the bindings from the same release; never mix a binding from one tag with a native from another.

Status codes

Out-params plus a status-code return throughout — no errno, no thread-local last-error required for correctness. 0 is success; every failure is a negative int32_t, stable forever. The -1…-7 range is the frozen error taxonomy (shared with every binding); the -100…-103 range is ABI-boundary hygiene.

Handle lifecycle — fail-closed

All handles are opaque uint64_t registry ids. The lifecycle is fail-closed by construction:

  • Ids are never recycled. A disposed id is permanently invalid and can never alias a live object.
  • Poisoned after dispose. Handles are generation-tagged; any use after gc_*_dispose returns GC_ERR_DISPOSED_HANDLE and never dereferences freed state. Double-dispose is a harmless error, same code.
  • Explicit dispose is the only sanctioned release path. A binding’s garbage-collector finalizer may report a leak, never dispose — disposing from a finalizer would make release nondeterministic and could race a concurrent user. A binding MAY expose report-only leak diagnostics (a counter, a warning); those are diagnostics, not lifecycle.
  • Single-thread-or-caller-synchronized by contract. A handle is not internally synchronized for concurrent use; the caller serializes access to a given handle.

Memory contract

Fixed 32-byte reads — verbatim from the header

scalar32 is read as exactly 32 bytes — there is no length parameter; passing a shorter buffer is an out-of-bounds read. Bindings MUST length-check before calling. This applies to both gc_identity_new and the new_scalar32 argument of gc_rotate.

  • Opaque handles only for keys. Key material never crosses the boundary as bytes into a managed heap. Identity scalars and DEKs live and die inside the core.
  • Wire structures cross as bytes. Bundle / envelope / receipt JSON pass as const uint8_t* + uintptr_t len inputs, and results come back as a gc_buf handle you read with gc_buf_ptr / gc_buf_len and then release with gc_buf_dispose (which zeroizes the core copy). Copy the bytes out before disposing.
  • Strings are NUL-terminated const char*. member_id, keyexpr, and rs must be valid UTF-8 with no interior NUL (an interior NUL truncates silently, so every binding rejects it client-side; invalid UTF-8 is GC_ERR_BAD_UTF8).
  • Dispose zeroizes, best-effort, with a stated ceiling. Identity scalars, held DEKs, stream-key DEKs, and buffer contents are wiped on dispose. The honest ceiling — move copies, the AES key schedule, by-value returns at the conformance layer, and caller-managed plaintext — is enumerated on the Security page.
