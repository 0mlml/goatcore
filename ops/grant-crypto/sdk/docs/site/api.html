API reference

Five nouns, six verbs

The frozen v1 public surface is small on purpose. Each binding renders these names idiomatically — key_store.open() in Python, keystore.Open() in Go — but adds, removes, or reinterprets nothing. This page gives the language-neutral vocabulary first, then a per-language reference.

The nouns

Identity
A member’s id plus private key material (suite-typed). Unwrap-capable. Never serializable with key material in the clear; constructed from the member’s enrollment credential (a raw 32-byte P-256 scalar in v1).
Recipient
A member’s id plus public key material (suite-typed). Wrap-capable only. It exists service-side (the audience entry the key service wraps to) and is deliberately not on the consumer/producer binding surface — bindings never wrap.
Context
The required typed additional-authenticated-data binding: today the data topic (key expression). Mandatory on seal and open — there is no context-free overload.
KeyBundle
The wire structure the key service publishes on keys/<rs>/<gen> — the wrapped DEK for every member, signed. Parsed via the verbs; constructed only by the key service.
Envelope
The wire structure of a sealed data message — suite, release-set, generation, nonce, ciphertext. The in-band message body. See the wire format.

The verbs

The six verbs, language-neutral. The consumer order verify → slot → unwrap → open is enforced by construction, not by caller discipline.
VerbShapeMeaning
verify(bundle, trust) → ()Authenticate a bundle against the key-service verifying key. Consumers MUST verify before admit.
admit(keystore, bundle, identity) → had_slotUnwrap this member’s slot (if any) and retain the DEK for (rs, gen). false (no slot) is a normal outcome, not an error; fails closed on a malformed slot.
open(keystore, context, envelope) → plaintextOpen a data message with the held DEK for its (rs, gen); no-slot if none held.
acquire(bundles, rs, identity) → StreamKeyThe producer’s path to a seal-capable key: pick the highest generation of rs with a slot for this identity, unwrap it. No-slot if the producer isn’t in the audience.
seal(stream_key, context, plaintext) → EnvelopeOne-shot seal under the acquired key. No nonce, algorithm, or RNG parameter — the implementation supplies a fresh random nonce and stamps (suite, rs, gen).
rotate(identity, policy) → RotationReceiptMember-leaf rotation hygiene. Destroy (default) zeroizes the retired key, no re-wrap; KeepAccess re-wraps the member’s own still-live DEKs first (reducing FS). The receipt is a structured, self-dating fact.

Error taxonomy

Seven variants, frozen across all bindings. The capability-vs-reject distinction is load-bearing: UnsupportedSuite is a capability signal raised before any key operation; NoSlot (“not in the audience”) is a normal outcome; the read-side rejects are advisory, never a decrypt oracle. RotationRequired is the write-side local refusal at the seal cap — it changes nothing on the wire.

The frozen error taxonomy. C ABI codes are negative int32, stable forever; the full code table is on the C ABI page.
VariantCodeClassMeaning
UnsupportedSuite-1capabilityThe named suite is not implemented (signalled pre-key).
Decrypt-2rejectAEAD authentication failed (wrong key/gen/rs/topic, tamper).
Unwrap-3rejectThe wrapped DEK could not be recovered.
BadSignature-4rejectThe bundle signature did not verify.
NoSlot-5outcomeThe member has no slot / no held key (not in the audience).
Malformed-6rejectA field was malformed (bad base64/length/key encoding, bad JSON).
RotationRequired-7write-sideThe seal cap was reached; seal refuses until rotation.

Rust core

The grant-crypto crate, consumed directly (no C ABI). Three surfaces: the datapath module (the producer/consumer ergonomic), the rotate module (member-leaf forward-secrecy hygiene), and the crate-root free functions (the low-level wire layer plus key reconstruction helpers).

Suite constants

SUITE_V1 = "v1-ecdh-p256" (the only implemented suite) and SUITE_V2 = "v2-x25519-mlkem768" (reserved, inert). The service and pqc modules are the key-distribution state machine and the reserved post-quantum hybrid wrap respectively — see Wire format and Security → FIPS + PQC.

Exceptions form one hierarchy under GrantCryptoError: UnsupportedSuiteError, DecryptError, UnwrapError, BadSignatureError, NoSlotError, MalformedError, RotationRequiredError, DisposedHandleError, NullArgError, BadUtf8Error, InternalError. A leaked (unclosed) handle emits a ResourceWarning from __del__ — it never disposes.

TypeScript / Node

Package grant-crypto; koffi loads the shared library at runtime. Handles are classes with a static factory; call close() or use using (each implements Symbol.dispose). Branch on errors with instanceof, never on message text. Wire arguments are Uint8Array.

Errors are typed subclasses of GrantCryptoError (each with a numeric .code): UnsupportedSuiteError, DecryptError, UnwrapError, BadSignatureError, NoSlotError, MalformedError, RotationRequiredError, NullArgError, DisposedHandleError, BadUtf8Error, InternalError. The exported types RotationReceipt and ReWrappedDek describe the receipt shape. A garbage-collected unclosed handle emits a warning via a FinalizationRegistry — it never disposes.
