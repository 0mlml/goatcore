grant-crypto SDK

Encrypt data so only the intended members can read it.

A small, cross-language library for grant-keyed encryption. Encryption and decryption happen entirely inside your process. The platform distributes wrapped keys but never holds one that can read your data, and rotating your key destroys the old one so past traffic stays unreadable.

We already encrypt data so that only the people a data owner grants can read it — and, importantly, no server anywhere holds a key that can decrypt; only each recipient, on their own machine, with a key only they hold. The one thing that would make it even stronger — forward secrecy, so a machine seized next year reveals nothing about last year — can’t be forced from the outside, because we don’t own the recipient’s computer. So this library wins it the other way: make the safe behavior the automatic default, and make the library good enough that people adopt it because it is the best tool for the job. That framing is the whole point of the design (ADR 1106).

One audited core (Rust) sits behind a hand-authored, versioned C ABI; thin Go, Python, and TypeScript wrappers call the same core. Every binding is the same library — the same wire format, the same conformance vectors, the same behavior.

The four invariants

These hold across every binding and are guarded in the design; if a choice would break one, it is the wrong choice.

  • The platform holds no keys. The key service mints a data key (DEK), wraps it to each authorized member, publishes the bundle, and drops the DEK. Its API exposes no function that returns plaintext or a DEK.
  • Only members decrypt, in-process. A consumer returns plaintext only to the holder of the member identity key. A non-member has no slot; admit fails closed.
  • The producer is not a key authority. seal takes no recipients — a producer seals under a stream key unwrapped from its own bundle slot. Only the key service resolves an audience and wraps.
  • Forward secrecy is endpoint-enforced. Default rotation destroys the retired private key with no re-wrap of anything. Losing pre-rotation re-fetch is the forward secrecy. The platform can never re-wrap — it holds nothing to re-wrap.

How to get it

On-mesh developers fetch the SDK from the mesh-internal download surface at get.<site>.<zone>/sdk/ — the prebuilt C ABI libraries (linux/darwin × amd64/arm64) and a source tarball, each with a SHA-256 checksum file. Always verify before use. The live rollout target is get.zagros.netbird.zagros.example/sdk/.

The Quickstart walks the fetch-verify-build path and then the one obvious flow in all four languages. The core and the C ABI ship in lockstep from one release tag — pull the library and the source from the same release.
