Troubleshooting

When something doesn’t work

The two most common first-run problems are the native library not being found and a checksum that does not verify. After those, this page maps the error variants to their real causes and covers the toolchain floors and the macOS dylib note.

Finding the native library

The Go binding links the static library at build time; the Python and TypeScript bindings load the shared library at runtime, resolved from the GRANT_CRYPTO_CAPI_LIB environment variable. Its semantics differ slightly by binding:

BindingHow it locates the native
Gocgo links libgrant_crypto_capi.a statically. The cgo directives default to ../../target/debug relative to the package; a release build overrides the LDFLAGS search path to the shipped, checksum-pinned static library. On Linux the core also needs -lm -ldl -lpthread (wired in the directives); macOS needs nothing beyond libSystem.
PythonGRANT_CRYPTO_CAPI_LIB may be the library file or the directory containing it. Resolution order: (1) that variable; (2) the Cargo dev build under ../../target/{debug,release}/; (3) the platform library bundled next to the package. If none is found you get a clear RuntimeError naming every path tried and the build command.
TypeScript / NodeGRANT_CRYPTO_CAPI_LIB is the full path to the shared library file; koffi loads it at runtime. Without it, a relative dev-path search finds a local cargo build output.
Quick fix

Unpack a prebuilt grant-crypto-capi-<os>-<arch>.tar.gz and point at it: export GRANT_CRYPTO_CAPI_LIB=/path/to/unpacked/dir (Python) or =/path/to/libgrant_crypto_capi.{so,dylib} (TypeScript). For Go, set the cgo LDFLAGS search path to the unpacked directory that holds libgrant_crypto_capi.a.

Verifying checksums

Every artifact ships a sibling .sha256, and the release carries an aggregate SHA256SUMS. Verify before use — the download surface carries no app-layer auth beyond the mesh gate, so the checksum is your integrity check.

A mismatch means a truncated or corrupted download (retry the fetch) or the wrong file for the checksum — the .sha256 names its file, so confirm you fetched the matching pair. The source-tarball name carries the version (grant-crypto-sdk-0.1.0-src.tar.gz); a name that disagrees with the served version.json means the tag and the built artifact are out of step.

Common errors and their causes

Error variants are advisory (see Security), but each maps to a real, actionable cause. The names below are the language-neutral variants; each binding renders them idiomatically (ErrNoSlot, NoSlotError, and so on).

ErrorLikely causeWhat to do
NoSlotYou are not in the audience for this release-set, or you hold no key for the message’s generation (you were not admitted to that (rs, gen), or you were revoked at a later generation).Confirm the member id is in the bundle’s audience and that you admitted the bundle for the message’s generation. For a producer, NoSlot from acquire means you are not in any visible audience — the key service must include your id.
RotationRequiredThe stream key hit its cumulative message-count cap; seal refuses rather than risk nonce reuse.Rotate to a new generation (the key service publishes it) and re-acquire — a new generation starts with a fresh budget. Re-acquiring the same generation will not help; the count carries forward. Watch remaining() to act before the refusal.
DisposedHandleUse after close()/Close()/.close(), a double-dispose, or a handle from a different (or already-collected) object. A lifecycle bug in the caller.Ensure exactly one dispose per handle and no use afterward (defer Close() in Go, with/using in Python/TS). A leak warning from a finalizer means you forgot to close — the finalizer never disposes for you.
DecryptAEAD authentication failed: wrong topic (the key expression is AEAD-bound), wrong key/generation/release-set, or tampered bytes.Open with the exact key expression the message arrived on. Do not branch program logic on which reject occurred — it is not an oracle.
BadSignatureThe bundle signature did not verify, was absent, or you passed the wrong verifying key.Verify against the correct key-service verifying key (SPKI DER), or validate the carried signer_svid against the SPIRE root. Do not admit an unverified bundle.
UnsupportedSuiteThe data names a suite this build does not implement (e.g. the inert v2). A capability signal, raised before any key operation.Use a build/suite that supports the data. This is safe to branch on — it reveals nothing about keys.
MalformedBad base64/length/key encoding or bad JSON — or a scalar of the wrong length, or a set_cap request above the default.Check the wire bytes and that scalars are exactly 32 bytes. set_cap can only tighten.

The macOS dylib note

The release signs the shared library on macOS — Developer ID plus notarization when the signing secrets are provisioned, otherwise a proper ad-hoc re-sign that clears the fragile linker-signed signature the Rust linker emits. A consumer’s loader trust-evaluates that signature when it dlopen()s the library, so the re-sign matters even for local use. The static library (.a) is an ar archive, not a Mach-O, so it is not code-signed and ships as-is.

If macOS refuses to load the dylib

An un-notarized ad-hoc build may be blocked by Gatekeeper on first load. Prefer a release built with the Developer ID + notarize path, or clear the quarantine attribute on a library you fetched and verified yourself (xattr -d com.apple.quarantine libgrant_crypto_capi.dylib). Verify the checksum first — only clear quarantine on bytes you have checked.

Where to get help

  • The binding READMEs. Each binding’s own README.md, shipped in the source tarball at grant-crypto/sdk/bindings/<lang>/, is the authoritative, CI-tested quickstart and error reference.
  • The runnable examples. bindings/go/example_test.go, bindings/python/examples/quickstart.py, and bindings/ts/examples/quickstart.ts each walk the full flow and are CI-tested, so they can’t drift from the API.
  • The mesh surface. The SDK, its checksums, and this documentation are served at get.<site>.<zone>/sdk/ (docs at /sdk/docs/); /sdk/version.json tells you exactly which release is being handed out.
  • The normative wire spec. ops/grant-crypto/WIRE-FORMAT.md in the source tarball is the canonical wire contract if you are building or debugging an independent implementation.
