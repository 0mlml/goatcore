01 · The problem

There is no universal identity — and almost no one attempts one.

The big problem: every platform, org, nation, and vendor defines identity its own way — a person, a unit, a machine is a different, incompatible record in each. Connecting many systems then means bespoke N×M mappings, meaning lost in translation, and trust that doesn't carry across the seam. A single coherent identity spanning commercial / government / allied / civil actors and people / systems / processes is rare-to-nonexistent, and that absence is the ceiling on interconnecting systems at scale — the exact problem a NATO-scale backbone lives or dies on.

The same disease, in miniature, inside our own stack: the identity model is sound but fragmented across ~13 hand-maintained places — no one artifact is simultaneously the human narrative and the programmatic source of truth, and it already bit us (the civil kind landed in one schema but not another). CI guards catch drift, but a guard is a band-aid over fragmentation; refusing to fragment even at the smallest scale is the precondition for the universal model we ship outward.

Machine codification

manifest schema (×2 synced) + three Kratos identity-schemas + a NetBird taxonomy + cert URI-SAN grammar — fragmented, guarded by convention.

The inversion we agreed on: not a prose spec kept in lockstep with schemas by a drift-guard — instead a structured SoT that generates both the enforced artifacts and the human reference. Divergence becomes structurally impossible, not caught-after-the-fact. Derivation is strictly one-way: SoT → docs, never prose parsed back (parsing narrative into truth is non-deterministic — the anti-pattern to never commit).

02 · The insight that reshapes the model

Universal identity spans three sources that don't natively align.

“Universal” isn't one taxonomy — it's the reconciliation of three provenance worlds, each with a different authority. The grammar must record which world each value comes from, or it silently pretends they're one.

1 · doctrinal

Existing mil identity

People, orgs, things, systems, processes that already have external identity: UIC, LOGFAS ORBAT, DODAAC, echelon doctrine, STANAG-1059 nation codes. goat conforms + maps where they're correct + applicable — but they're often latent, non-unique, coarse, or nation-scoped, so they ride as graded attributes on goat's native spine, not as the key.

2 · native

Novel goat identity

New ground doctrine doesn't cleanly name: node-class PROCESSOR/PLATFORM, autonomy, affiliation civil, the typed edge catalog, the slot/anchor model. goat is the authority; canonical-to-us.

3 · industry

Best-practice patterns

Structure adopted from the field, absent in 1 & 2: SCIM extension model, SPIFFE SVID, Zanzibar tokens, W3C-VC spine, SKOS vocab shape, additive-only evolution. Shapes how, not what.

Do we account for this today?

Honest answer: partially, and only implicitly. The pieces are scattered and none is first-class:
  • 1 touched only by unit_code.source provenance — codes only, nothing else.
  • 2 exists (our node-classes, civil, edges) but is never labeled native-canonical vs conformant.
  • 3 acknowledged in prose (the descriptor doc cites SCIM/VC/Zanzibar) but not tracked as provenance.
There is no per-value record of which source, who the authority is, whether we may change it, and what it maps to externally — nor a rule for when the three conflict.
The fix (built into this design): make it first-class. Every vocabulary/value in the SoT carries an authority: doctrinal | native | industry axis, a mappings crosswalk (to the external code where doctrinal), and a basis ref (the STANAG/RFC or the ADR that made it native). The SoT becomes the reconciliation ledger — conflicts are recorded as explicit crosswalks, never silently merged. This formalizes the per-field source/authority provenance the identity-descriptor standard already reserved (ADR 1051 §7) — continuity with the prior universal-identity work, not a new parallel concept.
Doctrine is a claim, not ground truth. A doctrinal identifier (UIC, LOGFAS, DODAAC) is often latent/stale, incorrect, non-unique, too coarse to identify the actual system/process, or valid only within one nation. So it cannot be the primary key. goat's native anchor (the UUID/slot) is the identity spine — chosen because it's the one identifier guaranteed unique, specific, and universal across all three worlds. Doctrinal codes attach to the anchor as graded, scoped, possibly-plural attributes; identity never depends on one being correct or present.
LayerReconciliation rule
native anchor UUID / slotThe authoritative identity spine and the join key for everyone — guaranteed unique, specific, universal. All reconciliation and de-duplication happens here; nothing subordinates it to an external code.
doctrinal codeA mapped attribute, not a key — and typically plural, imperfect, coarse, or nation-scoped. Attached to the anchor with source · scope · confidence · as_of; may be several, may be absent. goat conforms where doctrine is correct and applicable and records the delta where it isn't (doctrine-says-X / goat-assesses-Y) — it can be a correcting authority, not a passive conformer. Never renames; never inherits the error.
native valuegoat is the authority; evolve additively. When doctrine later canonicalizes it, add a mappings crosswalk — never rename (born-as cert invariant).
industry patternProvides the mechanism that makes the above hold: a universal UUID spine (SPIFFE-style), scoped + graded mappings (SKOS), effective-dating. Adopt + cite; don't reinvent where a mature standard exists.
conflictRecorded as graded, scoped mappings in the ledger + surfaced in docs. Interop emits the doctrinal mapping(s) for the target authority-domain, degrading gracefully when a code is absent or disputed — never a silent merge, never a subordination of the spine.

This is why unit_code is a mutable, source-graded registry attribute — not the cert-stamped identity. The architecture already anticipated imperfect doctrine; this makes the reconciliation rule match it.

03 · The approach

One SoT system generates everything.

Not one file — cramming distinct axes into one would re-conflate what the grammar deliberately separated (the schema itself warns ADMIN mesh-role ≠ ADMINS service-group). One system: axis-separated structured vocab files, one deterministic generator, one governance model, one human spec.

Nothing flows back up. Prose → doc; SoT → doc; never doc → SoT. A git diff regeneration gate fails CI if any generated content was hand-edited.

This isn't invented — it's generalized. ops/permissions/group-permissions.yml is already a structured SoT with check-ory-groups-enum.sh guarding a schema enum against it, and ops/serve/services.yaml → generate.py already generates Caddyfile + compose + health checks. We are promoting an established local pattern from guard to generate, across all identity vocabularies.

Where this sits in the arc: this is the foundational vocabulary layer of universal identity. The identity-descriptor standard (ADR 1051) packages and ships this grammar (its §8 already defers to identity-grammar as the field schema); the actor-relationship graph projects it; the RFC narrates it. The SoT is the one machine source they all derive from.

05 · Best practices — how the field does this well

YAML SoT + generator, SKOS metadata, SCIM discipline.

Format: YAML + generator — not CUE

Our SoT is a controlled vocabulary (closed enums + per-value metadata) — that's data, not schema-logic. Heavy schema languages (CUE, Protobuf, Smithy) earn their cost only for constraint systems. And half our outputs aren't schemas (cert value-sets, NetBird groups) — a generator handles those; a schema-native SoT can't. Emitted JSON Schema uses $defs/$ref + bundling.

Per-value envelope: SKOS-shaped

Each value carries definition · deprecated+superseded_by+date · external mappings — one envelope feeds the schema description and the doc glossary. Deprecate-don't-delete keeps structure intact so nothing breaks.

Discipline: SCIM extension model

Freeze dimension semantics centrally; grow only through a named, versioned extension — never by mutating a value's meaning. OpenFGA/SpiceDB validate the friendly-source → generated-JSON flow in production; Kratos consumes JSON Schema directly.

Docs: generated between markers

markdown-magic markers splice generated tables into the human spec; json-schema-for-humans emits the full reference; a git diff gate fails CI on hand-edits — the discipline the DNS registry already uses.

Evolution rules (hard, borrowed from protobuf/Avro/SCIM canon)

  • Additive-only. Adding a value is safe; removing/renaming strands issued certs + Ory identities.
  • Deprecate, never delete; never reuse a retired token string.
  • Issued-credential invariant: a value ever minted into a cert or Ory identity stays valid forever — the enum only grows; the registry handles "currently-is."
  • Closed enums fail-closed on machine paths, with a reserved experimental block for values-in-trial.
  • Semver the vocabulary + stamp the version into every generated artifact header — the same additive-minor / fail-closed-on-unknown discipline as the descriptor's ?v=<major> document-schema negotiation (ADR 1051 §5), one layer down.
  • Federated governance: additive PRs fast-path (CI proves additive-only); removals/renames get heavyweight ratification — so the SoT is never a serialized-approval chokepoint.

Optional later (not v1): a CUE subsumption gate to machine-prove each new grammar version is backward-compatible — the one thing a plain script can't do.

06 · The SoT shape

grammar.yaml — SKOS envelope + the three-source axis.

Two things, deliberately not blurred: the envelope — the fixed shape every value fills — and a worked example of real values in that shape. Per-value definition strings are migrated from the existing vetted tables (identity-grammar.md §1.3, GLOSSARY, ADR 1043) — the SoT inherits semantics, it doesn't reinvent them.

a. The envelope (the shape — a template)

# the shape EVERY value fills. Angle-brackets are placeholders, not literals.
<dimension>:                 # e.g. affiliation.kind | echelon | node-class
  closed: true                # closed enum → fail-closed on machine paths
  rides: [<surface>, ...]     # manifest | ory-aff-claim | cert-uri-san | netbird-group | registry
  values:
    <value_token>:            # the machine token, verbatim (e.g. COMMAND)
      definition: <str>       # DEFINES the value as a classification — never a synonym for the token
      authority: doctrinal|native|industry
      basis: <str>            # the external standard (doctrinal) OR the ADR that made it native
      mappings: { <domain>: <code> }  # crosswalk to external identifiers, per authority-domain
      scope: <str>            # where it's valid: national | nato | universal — for non-universal doctrine
      added: <date>
      deprecated: <bool>
      superseded_by: [...]      # if deprecated: decomposed but kept valid, never deleted

b. A worked example (real values, real definitions)

# definitions lifted from docs/design/identity-grammar.md §1.3 + ADR 1043
echelon:
  rides: [netbird-group, cert-uri-san]
  values:
    COMMAND:
      definition: "Top command-authority tier — a combatant / theater command; broadest legitimate site-scope (theater / multi-site)."
      authority: doctrinal
      basis: "US joint-echelon doctrine"
    OFFSITE:
      definition: "Deprecated catch-all that conflated geography + echelon + role; decompose into those three."
      authority: native
      deprecated: true
      superseded_by: [echelon, role, affiliation]   # kept valid so issued certs don't break

affiliation.kind:
  rides: [manifest, ory-aff-claim, cert-uri-san]
  values:
    civil:
      definition: "The principal belongs to a non-governmental civil-society organization — academia, an independent researcher, an NGO, a non-profit."
      authority: native
      basis: "ADR 1043 Amendment 1"
      added: 2026-07-01

unit_code.scheme:            # the SCHEME is doctrinal; a specific code's correctness /
                          # uniqueness / scope is graded PER-INSTANCE in the registry
                          # (unit_code {source, scope, confidence, as_of}), never assumed.
  values:
    sovereign:
      definition: "A nation's own unit-identity scheme (e.g. the US 6-char UIC)."
      authority: doctrinal
      scope: national
      mappings: { us: UIC }

Directory: grammar.yaml (the ADR-1043 dimensions + person/system/status/autonomy/unit_code/edges) beside service-groups.yaml (ory_site + ory_idp groups, folding in group-permissions.yml) — one axis per file, one generator over all. The top-level version is stamped into every generated artifact.

09 · Decisions

Confirmed for this build.

  • Invert to generate-from-SoT (not prose+guard); one-way SoT→docs derivation.
  • One SoT system, axis-separated files — grammar.yaml owns the identity-grammar dimensions; service/idp groups stay a sibling vocab under the same generator (keeps the axis-separation the grammar fought for).
  • Location: machine SoT + generator at ops/identity/ (matches ops/serve/, ops/permissions/); human spec at docs/design/identity/.
  • Format: YAML + deterministic generator; SKOS per-value envelope; + the three-source authority axis (new, from this review).
  • Governance: additive-only, deprecate-never-delete, issued-credential-invariant, semver, federated fast-path.
10 · Build plan

Four increments, review at the gate.

1 ADR + grammar.yaml

"Identity grammar as generated SoT." Capture today's full vocabulary in the SKOS + authority envelope. No downstream change yet.

2 Generator — byte-for-byte gate

Reproduce the current manifest-schema + Kratos enums exactly. Stop here for your review — the proof it works before touching anything.

3 Flip targets + regeneration gate

Schemas/taxonomy/cert value-sets become generated; wire the git diff gate; retire the 2 guards; cover ory_idp.groups.

4 Human spec + cleanup

docs/design/identity/ spec with generated tables + the three-source crosswalk; audit/retire the stale Kratos schema; CLAUDE.md pointer.

What excellent looks like

  • One structured SoT; no enum value defined anywhere else in the tree — a CI grep proves it.
  • One deterministic generator emits all schemas + taxonomy + cert value-sets + doc tables.
  • Every value: token · definition · authority · mappings · deprecated/superseded_by.
  • Additive-only CI gate; retired tokens never reused; minted values valid forever.
  • Docs generated-between-markers; a git diff gate fails on hand-edits.
  • The three-source reconciliation (doctrinal/native/industry) is legible in one read.
