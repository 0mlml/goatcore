## TL;DR (for a layperson)

goat goes open source as five repositories in the USAREUR-AF GitHub organisation: the core technology, its documentation corpus, its peripheral tools and demos, one worked example of a deployed environment, and the walkthrough that builds that example. All five start with fresh history and are produced from this repository by a pipeline that refuses to run unless every file has been assigned a destination and the produced trees contain none of our addresses, keys, names or places. This repository keeps running every goatnet unchanged; it becomes the private overlay of ADR 1197 when the pipeline reports zero substitutions in code for three releases running.

## Context

ADR 1197 chose the steady state — a public core consumed by pinned version from a private overlay — and left the seeding mechanics to an execution plan. Two earlier attempts at that plan exist and neither is used: the September 2026 go-open plan (fresh-history export, one public monorepo) was not executed, and a private scrub campaign (`goat-oss-prep`, frozen 2026-08-27) produced a tree whose own sign-off read "content 100% clean" but which an independent scan did not pass, and which had fallen far behind `main`. The lesson taken is procedural, not personal: a scrub is only as good as the independent gate that checks it, and a snapshot must be produced from `main` by a repeatable pipeline, never by a campaign.

## Decision

1. **Five repositories in `USAREUR-AF`, created 2026-11-02, private until the operator flips them.** `goatcore` (the substrate: `goat`, `goatbuilder`, `goat-errors`, `panoscope-core`, the relay and signal server, the Ansible roles and generic playbooks, the CI gates, the ADR register, the design docs of shipped core components, the books and the tutorials); `goatdocs` (the explanatory corpus: design docs not tied to a shipped component, the design system, reference, manifesto, integrations, partner and vendor templates); `goatstuff` (peripheral surfaces and demos: panoscope, stethoscope, flashlight, netvis, microscope, trashgoat, goat-topology, gym, the example apps, synthetic vendors, the sandboxes, with their roles, playbooks and docs); `goatenv` (one goatnet's overlay — group_vars, inventory, pins, enrollment manifest, DNS zone, operators, warrants — for the synthetic goatnet `zagros`, generated by goatlite's renderer from four invented facts, so no real configuration is read; the template every adopter's overlay and this repository's future overlay follow); `hello-galaxy-goatenv` (the walkthrough that builds `goatenv` from `goatcore`, in the shape of the other Hello Galaxy repositories; it replaces the earlier `hello-galaxy-goatnet-from-scratch`).
2. **Owner control is the GitHub team `USAREUR-AF/goat-owners`** — four named owners — with `admin` on all five repositories and no other grant. Branch protection on each `main`: one approving review from a code owner, signed commits, DCO, required status checks, enforced for administrators; secret scanning and push protection on from creation.
3. **Fresh history, produced by a pipeline in this tree.** `ops/oss/allowlist.yaml` assigns every tracked path to exactly one of `core`, `docs`, `stuff`, `env`, `private`; documents are private by default and cross only when listed in `ops/oss/docs-released.txt` after a full read, because many describe real operations and substituted names over the same facts still report the facts; `ops/oss/export.py plan` refuses while any path is unassigned; `ops/oss/export.py export` writes the per-repository trees, applying `ops/oss/substitutions.yaml` (built by `ops/oss/build-substitutions.py` from a hand-kept seed plus every mesh address, public infrastructure address, EC2 id and operator e-mail derived from this tree) to contents and paths; `ops/oss/leak-gate.sh` then fails the export on any shape (keys, addresses outside the documentation ranges, account ids, personal or government mailboxes, markings) or any identifier derived from this tree's own inventories. The seed is private and committed; the built dictionary is gitignored and rebuilt at export time. Commits in the public repositories are grouped by component but every commit is a strict file-subset of the final gated tree, under one designated release identity; no dates or authors are reconstructed.
4. **Re-addressing is part of the export.** Go module paths `github.com/<private-org>/goat/...` become `github.com/usareur-af/goatcore/...`; `ghcr.io/<private-org>/` becomes `ghcr.io/usareur-af/`; `goatstuff` consumes `panoscope-core` from `goatcore` by git tag; `hello-galaxy-goatenv` pins `goatcore` by `GOATBUILDER_REF`. Release binaries and images are rebuilt by `goatcore`'s own workflows, into its releases and `ghcr.io/usareur-af`. Existing assets are not copied: `goat` compiles in its goatnet list and ACL declaration, so a binary built from this tree carries deployment names. This repository's pins keep `ghcr.io/<private-org>` until it becomes the overlay.
5. **Apache-2.0 on all five repositories**, copyright "U.S. Federal Government (in countries where recognized)" per the code.mil guidance, because the U.S. Government created the code and has approved its release to everyone; later contributions stay with their contributors under the same licence; NOTICE and THIRD_PARTY_LICENSES carry the AGPL process boundary of ADRs 0110/0111. Each repository carries README, CONTRIBUTING (trunk-based, PR-gated, DCO `-s`, Conventional Commits, squash), CODE_OF_CONDUCT, SECURITY (private vulnerability reporting), GOVERNANCE and CODEOWNERS written for contributors who are not us.
6. **This repository keeps running every goatnet unchanged.** The export reports substitutions in code paths per run; when that number is zero for three consecutive `goatcore` releases, this repository is renamed and becomes the private overlay of ADR 1197, consuming `goatcore` by pin. Until then it is the source and the public repositories are its exports; contributions from outside land as ordinary PRs on the public repositories and are replayed here.

## Alternatives considered

| Alternative | Why not |
|---|---|
| Re-freeze and reuse `goat-oss-prep` | Its gate passed a tree an independent scan did not; it is far behind `main` with whole components unruled; bringing it current is a second campaign the size of the first, and campaigns do not repeat on every release. Its dictionary and ship-list were read as input to the seed and the allowlist. |
| Two public repositories on day one, split later | The operator wants all five released together; the per-file rulings cost the same whether applied now or later, and the seam between core and peripheral is one crate dependency (`panoscope-core`), resolved by a tag pin. |
| Reconstruct a history that mimics the original | Every public commit is a published tree that must pass the gate; mimicked intermediate file states are N trees to verify instead of one. Subset-of-final grouped commits give readable history for the cost of verifying one tree. |
| Publish from the private organisation | The operator names USAREUR-AF as the organisation; the private organisation keeps the private repository and its image namespace until the overlay flip. |

## Consequences

- The seam is reviewable data in this tree, run on every PR (`ops/oss/export.py plan`) and on a schedule (the full export and gate), so a new directory with no ruling fails CI here before it can reach a public tree.
- Every substitution in a code path is a defect to fix at the source here; the count is the gauge for the overlay flip (D6).
- ADR 1197's slug `<private-org>/goat` for the public core and ADR 1195's single image namespace are superseded as stated in the header; the steady-state relationship of 1197 is unchanged.
- Release approval and the copyright holder are settled (operator, 2026-11-02). The visibility flip remains the operator's act, after the final opsec read of the private repositories.
