## TL;DR (for a layperson)

We can already write down what each of our environments is *supposed* to run, and every machine already keeps its own receipt of what it actually installed. What we could not do was compare those two things the same way twice — the comparison existed once, buried inside a script that produces one report file, so every new way of looking at it would have re-invented the rules and quietly disagreed with the others. This decision makes the comparison a foundation: one machine-readable, signed "this is what environment X should be running" file that every tool reads (people still edit the friendly version); one place where the rules for "matches / differs / can't tell" are written down, tested against shared examples so the two programming languages that have to apply them cannot drift apart; one small report each machine publishes about itself onto the messaging fabric we already use for health readings; and — built last, on purpose — a web page that shows all of it at a glance and, for anything out of line, prints the exact command to fix it. That last rule matters more than it sounds: the fix is always "run the setup again," never "go change this one thing by hand," because hand-fixes are how the mess started.

## Context

Two halves of the consistency question are built and neither can reach the other.

The **intent** half landed 2026-08-02: `ops/pins/fleet-pins.yaml` plus `generate-pins.py` render every governed goatnet's image pins from one table, CI-gated, and `report.py` renders a committed stage-1 parity report from it (`environment-parity.md` §3/§5). The **live** half has been fleet-wide since 2026-06: every one of the 55 deploying roles writes `/var/lib/goat/<component>/deploy-history.jsonl` through a shared role, fail-closed-ratcheted at zero gap, live-fired on ZAGROS ([ADR 1060](1060-universal-deploy-rollback-ledger.md), M-075).

Nothing joins them. `parity-report.md` states it on every render: "Live host state — everything. No host is contacted."

`environment-parity.md` §5 already describes the model that would join them — two fact kinds, one comparison function, every surface a projection with no private collector or semantics — and adds a maturation contract binding each successor to retire its predecessor in the same change. But the model has no enforcement behind it, and three specific gaps stand between it and a foundation: intent has no *artifact* (only a table and a resolver, so "what is intent" depends on which checkout you ran), the comparison semantics live inside one renderer (reachable only by importing a hyphenated script through `importlib` — which `report.py` already does), and the live half has no shape at all.

The operator ask (2026-08-04) is explicit about both the substance and the order: the parity/fleet machinery needs "a good foundational underpinning of true source rigor and observability and alignment with idempotence — not just a dump into a repo or a markdown file spread across many dimensions"; then, after foundations, "a web app view for convenient rapid assessment and pointers to remediation when things become out of sync."

## Decision

**D1 — IntentV1 is the consumed source of truth; YAML stays the authoring surface.** One schema-validated artifact per goatnet at `ops/consistency/intent/<goatnet>/intent.json`, generated deterministically from the committed tree by the existing pin generator as a second output, carrying every value already resolved per member **with its resolution state attached** (`resolved` / `unset` / `unreadable` / `absent` — the distinction `report.py` keeps deliberately apart, which a consumer holding only the artifact cannot recompute). Humans continue to edit `fleet-pins.yaml` and `parity-capabilities.yaml`, where `reason:` and `why:` live next to the value; **no consumer other than the generator parses them.**

- **Canonical JSON + a committed JSON Schema, not protobuf.** The dividing line, stated once: JSON on disk and in the PR, protobuf on the wire, and the bus never carries intent — only a reference to it. Four reasons: the established signing pattern signs SHA-256 over exact file bytes of a JSON document ([ADR 1082](1082-name-fallback-resolver-signed-snapshots.md)), so reusing it needs a byte-stable text artifact and no new key infrastructure (ADR 1109 P14); a generated intent is only worth committing if it is *reviewable as a diff*; its producers and consumers (Python generator, shell CI gate, a node fetching over HTTP, a browser) are not on the bus, so codegen buys nothing; and both precedents exist unambiguously in-tree (`ops/operators/schema/`, `ops/devices/schema/` for committed JSON + schema; every `EnvHealthV1` domain for protobuf).
- **Generation identity is `content_hash` + a monotonic `serial`; the git commit is provenance stamped by the actuator.** §5 defines a generation as "identified by the git commit that produced it," which is right about intent and mechanically impossible for a committed file — a file cannot contain the hash of the commit containing it. The comparison key is therefore the content hash, which both sides can compute; `serial` and `generated_at` move **only when the body changes** (the name-snapshot rule, and what keeps `--check` stable); and the deploying checkout's `HEAD` is recorded by the Ansible run into the node's applied-intent stamp. This is also a correctness property, not a convenience: two commits routinely produce identical intent, and comparing on commit would grade every node diverged after every unrelated merge — a false red with a mechanism behind it.
- **Committed and `--check`-gated, not a per-commit CI artifact.** A CI-only artifact hides input changes from PR review; a committed one goes stale, which `--check` closes. The tie-breaker is that a node must be able to fetch intent with the WAN down for 30 days ([ADR 0206](0206-island-mode-by-construction.md)), and a build output has no offline story while a signed committed file has the one name snapshots already use.
- **Migrating consumers:** `report.py`, the queued stage-2 live join, the rollup meter, the console, `goat health --domain consistency`, and ADR 1109 FM-2's site-local replica. All read IntentV1; none re-resolves the tree.

**D2 — One grading library; the grammar is data, versioned once, and executed only under a shared corpus.** `report.py`'s resolution and grading semantics move into `ops/consistency/` as an importable package, with the grade grammar as a committed SoT (`grammar.yaml`) — the [ADR 1067](1067-identity-grammar-generated-sot.md) pattern of a vocabulary SoT plus a CI reproduction gate. The library is the **only** place comparison semantics live; a projection may choose what it can see and how it renders, never how it grades.

- **One grade is added: `unaccountable`** — a node reporting a ref, hash or render that no generation in the tree explains, as distinct from `SKEW` (a node behind, where every value is accounted for). They earn different grades because they demand different remediation: re-running the play fixes the first and *destroys the evidence* for the second, which is the F-272 / F-258 runtime-mutation shape and the observable the persistent-state rule has always lacked. Per `environment-parity.md` §5 rule 2, adding a grade requires amending that section, and that amendment lands in the same change as this ADR.
- **Two executions, one grammar.** Python is required repo-side (generators, CI, the renderer); Rust is required on-fabric, because the rollup must compute a color to publish an `EnvHealthV1` at all and the console holds a long-running Zenoh mTLS session ([ADR 0112](0112-tech-strategy-workload-shape-language-boundary.md)'s decision test; panoscope is the precedent). The rule that keeps that honest: **an implementation is permitted only if it passes the shared golden corpus in CI, and no implementation may define a grade.** The corpus lands with the extraction, not after it, and pins remediation pointers alongside grades.
- **Acceptance for the extraction is byte-identical output.** `parity-report.md` must regenerate unchanged through the library; a semantics extraction that changes output is either a bug or an undeclared decision.

**D3 — ConsistencyV1 is a `oneof` arm on `EnvHealthV1`, not a surface beside it.** Following the time domain exactly: a per-node `ConsistencyReportV1` on `ops/consistency/report/<host_id>` (ledger tips, the intent generation the node converged against and its age, the config render hashes once declared, whether the intent signature verified), rolled by a passive reader into `EnvHealthV1{domain:"consistency"}` on `ops/consistency/health/<site>`. **The arm takes field number 15, leaving 14 on the `GnssDetailV1` reservation** ADR 1036 §3.2 already sketched. The record carries **facts, never verdicts** — a node cannot know whether its generation is current, because that is a comparison against a tree it may not have; grading happens at read time and is stored nowhere. The node's applied-intent stamp is written by the existing `rollback-ledger` shared role, so intent stamping inherits that role's already-green fail-closed coverage ratchet instead of starting a second coverage campaign; its role-entry ordering caveat is inherited too, and mitigated the same way `rollback.sh` mitigates it — reconcile against the live container before reporting.

**D4 — Remediation is a pointer, it is data, and the set is closed.** Every graded row that is not `match` or `declared` carries a `remediation` field emitted by the library — one of `reconverge` (re-run the named idempotent play), `regenerate`, `declare` (add a `deviations:` stanza with a reason), `rollback`, or `restore`/`rotate` where [ADR 1060](1060-universal-deploy-rollback-ledger.md)'s artifact-type dispatch says undo is a lie. **Never a bespoke mutation:** [`engineering-baseline.md`](https://github.com/usareur-af/goatdocs/blob/main/docs/design/engineering-baseline.md) §2.2 already decided that "drift is fixed by re-running, not by hand," and a consistency surface suggesting a targeted fix would manufacture the next `unaccountable` row with the authority of a dashboard. Because the pointer is a field rather than prose, every surface prints the same command for the same condition, and the library **refuses to emit a row that needs a pointer and has none** — the same fail-closed shape as "a deviation without a `reason:` is a schema error."

**D5 — The consistency console is a stateless projection, mesh-internal, and built after the foundations.** One page per goatnet served through the existing isitup/Traefik pattern at `consistency.<site_id>.<site_dns_zone>`, admin-gated through the existing Ory chain, one Rust binary with an embedded frontend (the panoscope shape). It holds **no private state**: intent from disk verified at read, records from the bus, comparison by the library, nothing stored, nothing surviving restart that is not re-derivable in seconds. It **renders** remediation pointers verbatim and copy-pasteable and **never executes** anything, holding no credential that could. It speaks the Block 94 deep-link contract (`site=`, `domain=consistency`) and mints no new param. A read-only cross-goatnet aggregator is the same binary with a wider input set — permitted to run rear/cloud, forbidden from being load-bearing. Sequencing is binding: the console is the sixth increment, because a console over re-derived semantics is the fifth copy of the model rather than the first view of it.

**D6 — Retirements are named per increment and land in the same change.** Per the `environment-parity.md` §5 maturation contract and ADR 1109 FM-1's absorption obligation: the increment that lands ConsistencyV1 **deletes `ops/pins/parity-report.md`** — deleted, not deprecated-and-kept — and moves its `--check` gate onto the intent artifact, which is the gate's real subject. `report.py`'s private semantics retire when the library lands; the `importlib` reach into `generate-pins.py` retires with them.

No new daemon on any node beyond the per-node publisher and the per-goatnet rollup meter — both siblings of the existing `goat-time-health` / `goat-mesh-health` meters, both reveal-only, neither in any enforcement path. Nothing in this ADR is built.

## Alternatives considered

- **Keep resolving intent from the tree per consumer; skip the artifact.** Rejected — "what is intent" then depends on which checkout a consumer ran against, which is the stale-trunk failure `ansible-preflight.sh` exists to catch, and it gives a node fetching intent over a 30-day-islanded link nothing to fetch.
- **Protobuf for IntentV1 too, for symmetry with the bus.** Rejected — the artifact's value is being reviewable as a diff and signable byte-exactly by the existing offline CA; a binary blob behind a `--check` gate teaches reviewers to trust the generator instead of reading it, and buys no wire efficiency for something that never rides a constrained wire.
- **YAML for the artifact, matching the authoring files.** Rejected — YAML has more than one valid rendering of the same document, which a byte-exact detached signature cannot tolerate. YAML stays where it is right: authoring, with comments.
- **Identify a generation by git commit, as §5 originally worded it.** Rejected as the comparison key (kept as the human-facing name) — a committed file cannot contain its own commit, and comparing on commit grades every node diverged after every doc-only merge.
- **One grade for all divergence; skip `unaccountable`.** Rejected — a node one bump behind and a node running an unexplained image need opposite first actions, and folding them makes the most interesting row in the matrix indistinguishable from the most boring one.
- **One implementation of the grading library, shared via FFI.** Rejected as over-engineering for a comparison that is tens of lines of precedence logic — an FFI boundary between a CI script and a Zenoh meter costs more than the corpus does, and the corpus is what actually proves agreement. Two conformant executions of one data-defined grammar is the cheaper guarantee.
- **A separate consistency surface (its own envelope, its own topic family, its own renderers).** Rejected — ADR 1036 exists precisely so a new domain plugs in with a `oneof` arm and a renderer arm; a parallel surface would need its own three altitudes and would drift from the honesty grammar the moment either changed.
- **Let the console keep history so operators can see drift over time.** Rejected — it would make the console the only holder of a fact, which is the line between a projection and an authority. Router-persisted `ops/**` plus the existing replay path already answers historical questions with no new storage.
- **Build the console first, since it is what the operator will see.** Rejected on the operator's own sequencing, and on the merits: a console over re-derived semantics is a fifth model, and the retirement discipline in D6 only works if the successor genuinely subsumes the predecessor's semantics rather than re-implementing them.
- **A standalone cross-goatnet consistency service that owns fleet consistency state.** Rejected — `environment-parity.md` §8 and ADR 1109 §6.2 both reject it by name; the permitted residue is a derived read-only projection that may render and may not decide ([ADR 1065](1065-graph-engine-property-graph-read-model.md) stance), which is what D5's aggregator is.

## Consequences

**Positive.** The join between committed intent and on-host truth becomes computable the same way by every surface, and every future surface inherits it instead of re-deriving it. The `deploy-history.jsonl` ledger — the best-maintained fleet fact the project has — gets its first consistency consumer. The stage-1 markdown file gains a named successor and a deletion date instead of becoming a palimpsest. `unaccountable` gives the persistent-state rule its first observable, so out-of-SoT mutation stops being a thing that is only discovered. Remediation-as-data means the answer to "what do I run" is reviewed as a corpus diff rather than written per surface. ADR 1109's FM-1 gains a specification, and FM-2 gains an intent document to pull.

**Negative / cost.** One more generated artifact per governed goatnet in every intent-affecting PR diff (the same cost `pins.yml` already imposes). Two implementations of one grammar, whose agreement rests on a corpus that must be maintained honestly — if the corpus stops covering a case, the guarantee quietly weakens. Two new always-on reveal-only services per goatnet at CF-3 (publisher, rollup) plus one at CF-6 (console), each with an image, a cert and a deploy. One new operator concept — the consistency grade — lands on the 1-week troubleshooting path, and **CF-6 owes a leak-register entry that cannot yet be written because the register itself does not exist** ([`complexity-budget-and-encapsulation.md`](https://github.com/usareur-af/goatdocs/blob/main/docs/design/complexity-budget-and-encapsulation.md), Block 81, designed-not-built); the obligation is recorded, undischarged, and gates CF-6's landing. The grade grammar grows from five states to six, which the maturation contract permits only with the §5 amendment this change makes.

**Neutral.** Nothing here is built; the first buildable increment is the intent artifact, and the gates are in `consistency-foundation.md` §9/§11, tracked as `consistency-foundation` in `backlog.md`. Composes with the environment-health surface (one more domain), the deep-link contract (no new param), and the rollback ledger (one more reader, plus one idempotent write in a role that already runs everywhere).

## Trigger conditions for revisit

- **A third language needs to execute the grammar.** Two conformant executions is a cost the corpus carries comfortably; three is the point at which an FFI or a single-service boundary should be re-argued rather than assumed away.
- **The corpus stops being the thing that changes when a grade changes.** If a grade edit lands without a corpus diff, the one-grammar guarantee has already failed and the mechanism needs teeth, not a reminder.
- **A consumer needs intent that IntentV1 does not carry**, and the proposed fix is to widen the artifact toward "all of group_vars" — that is the mega-unification non-goal returning in schema form, and it should be decided, not absorbed.
- **The aggregator acquires a reader in any enforcement path**, or anything starts depending on its availability. That is the brokerless line, and crossing it invalidates D5 rather than extending it.
- **ADR 1036's envelope reaches its `V2` fold-in**, which is the coordinated moment to reconsider whether the consistency publisher and rollup consolidate into the single `goat-env-health` meter that ADR §9 names as the clean end state.

## Status

**Proposed** pending ratification. Nothing decided here is built. The gate to in-flight is the intent artifact landing for one goatnet; the gate to canon is `consistency-foundation.md` §11's, which requires a measurement artifact showing a **true** consistency row that was previously invisible — the same evidence bar ADR 1109 sets for FM-1.
