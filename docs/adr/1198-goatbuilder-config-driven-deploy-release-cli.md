## TL;DR (for a layperson)

Today the steps to build and ship a release live in about a dozen separate shell and Python scripts. Each script knows one piece of the job, and the gaps between them cause real bugs. We will replace them with one tool, `goatbuilder`, that holds the whole set of guarantees — "a deploy applies exactly the version we declared and signed, re-running is safe, it isn't done until each machine itself confirms it, and every change can be reversed the same way it was made" — in one place. The tool reads a small config file describing a repo's components and environments, so the same tool works for our repo and for other goat teams' repos. It is built so that moving machines from being *pushed* their updates to *pulling* them is a setting, not a rewrite. We write the guarantees down first, then build the tool to enforce them, then replace the scripts one at a time — deleting each script as its replacement proves equal.

## Context

The build/release path is spread across `ops/scripts/rc.sh`, `deploy-component.sh`, `fastlane.sh`, `pr-land.sh`, `ansible-preflight.sh`, `rollback.sh`, `ops/release/graduate.py`, `ops/pins/generate-pins.py`, `cross-env-apply.sh` and `goat-standup.sh`. Each enforces part of an unwritten contract. F-586 is the failure that follows: `rc.sh` deployed from the operator's checkout, which need not carry the pin it had just merged, because no single component owned the invariant "a deploy applies the declared ref." The scripts also diverge in interface — some take JSON, some print prose, re-run safety differs — so the same operator action behaves differently depending on which script runs it.

Three forces make this the time to consolidate rather than patch. First, goat is going open-source with external dev teams who will run their own repos and environments (ADR 1197), so the tooling must be config-driven and bound to no repo, program or environment name. Second, deployment is moving from a push model (an operator runs Ansible against hosts) to a pull model in which each machine pulls a signed, serial-numbered declaration of its own desired state from the nearest registry and converges itself (ADR 1109; lab-demonstrated in *GitOps Reconciliation at the Edge*, draft), so the tooling must not assume push, must treat disconnection as a normal state, and must carry the signing seat. Third, a much simpler **goatlite** variant is planned, and must not require a second tool.

## Decision

Build **`goatbuilder`**, a separate, config-driven, generalized command-line that enforces a written deploy contract and subsumes the release/deploy scripts. The full design — the model, the converger interface, the config model, the verb taxonomy and the conformance suite — is in [`goatbuilder.md`](../design/goatbuilder.md).

1. **One model: declare, converge, verify.** A change is three distinct acts. *Declare* records the desired state — component, environment, class, immutable ref — in the one source of record, git (the pins and intents, authored and reviewed as a merge), and then *publishes* it in the form the environment's converger consumes: the merged files themselves for push, a signed index per environment with a serial that only increases for pull. Authoring and distribution are two jobs; git is where humans decide. *Converge* is the act of a **converger** — today an operator-driven Ansible push, tomorrow the on-host pull agent — reached through one narrow interface (`publish`, `observe`, `read_record`). *Verify* reads each machine's own record and compares it to what was declared, trusting the machine's record and never the converger's report of itself. The tool's own job is only ever to declare and to verify; it never reaches a host.
2. **A written deploy contract, C1–C10, ordered by phase.** Declare: C1 immutable content-addressed ref; C2 signed at the source and verified wherever consumed, and ordered so a consumer never accepts a declaration older than the last it accepted (git ancestry for the pins, a monotonic serial for the index) — a replay is harmless and a revert is a new declaration at an old digest; C3 fresh source, never a silent act on stale input; C4 attributed. Converge: C5 idempotent and resumable; C6 least-privilege transport. Verify: C7 verified-done *per machine*, where an unreadable record is *unknown* and a not-yet-pulled machine is *pending*, and neither is ever counted as done; C8 declared, actual and drift inspectable by read-only verbs. Cross-cutting: C9 reversible by a conforming declaration of the prior digest on the same path; C10 the machine contract — non-interactive, typed exit codes, output selectable as a table or as versioned JSON, YAML or NDJSON, declarative verbs distinct from read-only. The contract is enforced in one module and verified by a conformance suite.
3. **A separate binary from `goat`.** `goat` operates the running fabric; `goatbuilder` builds and ships environments and, in the pull model, holds the signing seat. They differ in audience, lifecycle and trust surface, so that authority stays out of the binary every participant runs.
4. **Config-driven and generalized.** No repo path, no goatnet or environment name, no program or goatnet-family name (`zagros`, `zagros_dev`, `zagros_prod`), and no transport is compiled in. A versioned, validated config declares a repo's components, its environments and the machine classes within them, their convergers, and the promotion path a change travels; the same released binary drives any repo, including one with no connection to ZAGROS. Generalization is verified by the conformance suite, so a config that passes behaves to contract.
5. **Push/pull-agnostic by construction, adopted per class.** The contract never mentions how a ref reaches a host. The converger is a config value per environment, overridable per class — the pull chain's unit of release is one class in one environment — so one class can move to pull while everything else stays on push, with no change to the tool or the other environments. `observe` is asynchronous: a verb reports converged, pending and unknown machines and never blocks on a fleet-wide "done." Promotion is one gate mechanism over typed stages: today's rungs, and for a pull-converged environment rings and geographic tiers on the same path.
6. **goatlite is a preset, not a fork.** `preset: lite` supplies batteries-included defaults over the same contract and binary; the preset layer is in the schema from the first version.
7. **Subsume and delete, both paths live during migration.** A verb ships only when it passes the conformance suite and a CI parity gate against the script it replaces; cutting over deletes that script and moves its documentation in the same change. No verb adds surface without removing its predecessor. Order by blast radius and churn: `release`/`deploy` first. The push→pull adoption follows the same discipline one class at a time.
8. **The one-hour goatnet is a design target.** `standup` is a first-class verb: one declaration for the whole site, every precondition checked by `doctor` before phase 0, resumable by phase and observed per machine, rehearsed on the mock fixture first — subsuming the sixteen phases of `goat-standup.sh` behind the contract. Target: a fresh goatnet declared → verified in 60 minutes or less on the four-node baseline (ADR 1141); the routine teardown-and-rebuild of `phoenix-architecture.md`. Status: designed; the first run measures it.
9. **Contract-first.** The model and the contract are fixed before any code. The config schema, full per-verb flag surface and conformance fixtures are the next design pass, the way `goat-cli.md` fixed its architecture before specifying each verb.

## Alternatives considered

- **Keep the scripts, patch each defect as it surfaces.** The F-586 class recurs wherever an invariant is split across scripts; the interface divergence and the per-script re-run rules remain; the push→pull shift would have to be threaded through every script separately. Rejected: it treats the symptom, not the split contract.
- **Wrap the scripts behind a thin CLI.** A single entry point without a single enforced contract leaves the invariants in the scripts it calls, so the gap that caused F-586 stays. Rejected: wrapping is not subsuming.
- **Add the verbs to `goat`.** Overloads the runtime binary every participant runs with build/release authority and, in the pull model, the signing seat. Rejected on least-privilege and on the audience/lifecycle seam goat-cli already draws.
- **Keep it bespoke to this repo (hard-coded paths and names).** Simpler to build, but useless to the external dev teams who will run their own repos and environments, which is a stated requirement. Rejected.
- **Build the pull agent and registry chain into `goatbuilder`.** Couples the tool to one converger's internals, the opposite of the interface that makes convergers swappable. Rejected: the chain and the agent are the pull converger's own parts; `goatbuilder` publishes into the chain and reads records back.

## Consequences

The contract becomes testable and uniform; the F-586 class is closed structurally rather than per-script. The script count falls as verbs land (the win is net reduction, enforced by delete-on-cutover). External teams get the same guarantees from the same binary via their own config. The push→pull migration and goatlite each become configuration over a fixed contract rather than new tools. Cost: a migration period where both paths exist behind a parity gate, a new Rust binary to build and distribute (the `goat-cli` build/distribution model applies), and a signing seat to operate once pull is adopted. This ADR records the decision, the model and the contract; it does not build the tool.
